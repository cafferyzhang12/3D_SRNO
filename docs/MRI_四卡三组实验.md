# 大容量四卡 MRI 配对重建

本次只运行直接回归、带干净端点监督的桥和无端点监督的桥。研究标识为 `x4_large_r2b`。沿用 3,919 个 TRAIN 病例、292,657 张切片、10 个完整 VAL 病例及历史固定的 84 个 TEST 病例。

## 目标与进度

A 在逆 Haar 后直接最小化像素 MSE。对于 B 的无图册直线高斯桥，记残差系数状态为 x、目标为 R。解析漂移满足 x+(1−t)f=R，x+tr=0。训练采用前向 (1−t)²、反向 t² 加权的漂移 MSE，取两项平均。这样每个方向的误差都换算为它在剩余时间造成的端点位移误差。两类原始漂移 MSE 仍逐轮保留。

带监督的 B 在此基础上加两种像素 MSE 的均值。一项来自条件真值路径上的干净端点，另一项从真实 LR 和零残差出发，按部署的 20 步和 η=0.05 生成状态，在最后一个内部时刻监督干净读出。第二项使用每个本地批次的八分之一，轨迹前缀停止梯度，最后一次读出参与反传。无端点监督的 B 使用同样的漂移目标，部署积分结果的 MSE 只用于记录。

研究日志给出混合 loss、分项 MSE、累计采样体块和优化更新数。每轮整病例 pooled MSE 决定最佳权重，同步给出 PSNR 和 SSIM。各方法总 loss 的含义不同，跨方法以相同病例上的重建指标比较。

## 训练预算与提交

两分支的宽度从 48/96/128 增至 96/160/256，直接回归有 15,346,544 个参数，桥有 15,388,032 个参数。数据量本身不足以确定最优容量，最终以整病例验证检查这次扩容的效果。

每组正式训练通过一个 Slurm task、四个 torchrun 进程使用同一节点的四张 A800，QoS 为 high。先在四卡上扫描内存和吞吐，再以同一批量给三组训练。此次实测每卡 256、全局 1,024。每轮采样 262,144 个 5×128×128 HR 体块，执行 256 次参数更新。训练上限 320 轮，至少运行 80 轮，连续 36 轮整病例 VAL 未改善才早停。每个阶段从独立 RUN_ID 开始；超时或抢占后续投沿用该 RUN_ID 的 last.pt。

```bash
# 在集群项目目录设置和历史数据一致的环境
export MRI_DATA_ROOT="$HOME/data/MRI_SR"
export STUDY_ID=x4_large_r2b
# MRI_CASE_INVENTORY、FIXED_TEST_MANIFEST 和 NEURAL_ATLAS_SRC 指向已核验的文件
bash scripts/submit_mri_large_trio.sh
```

本次部署目录另有已填好路径的 `bash start_large_trio.sh`。调度端复用已有作业。三组都完成整病例 VAL 后冻结，带监督的桥比较自身同一权重的端点与积分读出。三组均冻结后按固定病例清单分别提交四卡 TEST。有效配置、权重、曲线分别位于 `runs/mri/<RUN_ID>/experiment.yaml`、`bridge/{best,last}.pt`、`bridge/metrics.jsonl`，显存明细在 `reports/mri/x4_large_r2b/memory.json`。
